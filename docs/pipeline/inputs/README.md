# Research-pipeline inputs

Inputs are organized by task. The source archive includes fixed split/grid protocols and selected report case IDs; numerical match data are generated from the public SkillCorner files by stage 01. The output of that stage is `<output-root>/preprocessing/task_inputs/`, which is the default input root for later stages. Fold models and xT maps are generated by their preceding tasks.

## Shared tracking and partitions

`folds.json` lists the two test matches in each of five outer folds. Preprocessed tracking is saved at `<output-root>/preprocessing/matches/<match_id>/<match_id>_tracking.parquet`. `frame_states.py` uses the public state getter to reconstruct carry starts and pass releases. Pass probability additionally reads the observed target `r_target` from its generated `arrays.npz`.

## Task inputs

| Directory | Required observations and supporting inputs |
|---|---|
| `ball_drive/` | `rows.parquet`: 9,114 attempts, 456 losses. States are reconstructed from tracking. The physical fit supplies split-specific dispersion values to CatBoost. |
| `pass_probability/` | `rows.parquet` and `arrays.npz` with observed targets: 6,706 passes, 5,742 completed and 964 failed. Candidate trajectories and their reconstruction errors are generated from tracking. See [details](pass_probability/README.md). |
| `pass_selection/` | `rows.parquet`: 6,810 decisions, including 1,009 failed passes; `protocol.json`; `matches/<match>/players.parquet` linking event identities to tracking aliases. |
| `expected_threat/` | `events/{carries,passes,shots,losses}.parquet`, continuous coordinates and `protocol.json`. These are the xT cohort, not canonical carry observations. |
| `binary_classification/` | Action observations, residual labels, protocols and upstream artifacts; see [details](binary_classification/README.md). |
| `composed_risk/` | `labels.parquet`: 15,085 verified states, with `band_eligible` identifying the 14,919 terminal-covered states. Possession boundaries, carrier/team and next control are observed metadata. |
| `reports/` | `cases.json` selects the observed report possessions. |

Physical, xT and choice-model dependencies are written under `upstream/fold_0/` through `fold_4/`; production dependencies are under `upstream/production/`. `handoff.py` validates their match splits before connecting completed fits to downstream stages.

For pass selection, physical and xT artifacts use the matching six fitting matches. Screening results are generated by the pass-selection stage.

For xT, `protocol.json` distinguishes grid-comparison 8+2 splits, six-match downstream maps and the ten-match production map.

## Regeneration and verification

The [preprocessing stage](../preprocessing/README.md) reads original public files and writes tracking, possession, action, identity, event and task tables.

Pass-probability feature preparation first runs `generate_trajectories`, then `prepare_features`. The distributed pipeline retains both candidate trajectories and selects one method using only the fitting matches in each split. See [the task guide](../pass_probability/README.md) for the selection rule.

Composition uses the newly prepared features and fitted fold models. Report outputs never overwrite input tables.

Generated data are saved under `pipeline/outputs/<task>/`, with separate features, training, scores and production directories. xT additionally separates validation and feature maps; pass selection separates flat and CNL outputs; binary classification separates action and residual tasks. Choose a fresh output root for each execution.
