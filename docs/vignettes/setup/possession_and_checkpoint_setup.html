2 · Possession segmentation and context

This is the second part of the User guide, between datasets, installation and preprocessing and use on a match.

1. Three distinct units

  • Individual possession: one player’s control interval, identified by (match_id, possession_id). Its observed start and end must be matched to tracking for the interval table used here.
  • Team possession: a chain of individual intervals connected by verified completed passes. A completed pass changes the carrier without ending this team interval. Unverified continuity starts a new reconstructed team interval.
  • Canonical action: a one-second carry attempt or an instantaneous pass release. Its start state is a checkpoint at which the hazard h, the probability that the team loses possession during the next action, is evaluated.

A checkpoint is the start state of a canonical action. An additional snapshot is any other evaluated state; it lies outside the action sequence.

Frame evaluation is more general than action segmentation. A usable frame can be evaluated even if it is not a checkpoint. Segmentation supplies the conventional discrete action sequence underlying h; extra evaluations leave that sequence unchanged (Fernandez, Bornn, and Cervone 2021).

2. Canonical checkpoints

General rule

The checkpoints of an individual possession are the starts of its complete one-second carries, plus one terminal checkpoint that depends on how control ends: the release after a pass, the start of the final failed carry after a direct loss, and none after a foul suffered or a clearance.

Carries are anchored to the start of the individual possession, in successive one-second blocks. Each full successful carry supplies one checkpoint at its start. If control ends in a direct possession loss, the final failed attempt is retained even when it lasts less than one second. If loss occurs exactly at a full-second boundary, the last full block is the failed attempt.

A pass supplies a checkpoint at release, regardless of how much time has elapsed since the last full carry. A successful subsecond tail before a pass is an additional snapshot, left out of the final one-second carry benchmark and action-choice training.

Fouls suffered and clearances preserve preceding complete carries and end without a terminal pass/carry action; their terminal frames and short tails can be retained as additional snapshots. Shots are outside the fitted pass–carry task. The composed-risk benchmark separately defines the terminally covered cohort used for bands and reports.

get_actions() returns canonical actions; their frame_start values are the checkpoints. valid_only=True selects usable start states. include_snapshots=True also returns the annotated extras, marked by is_canonical=False. compute_risk_player_possession(..., include_snapshots=False) evaluates the canonical sequence only; frame_ids supports an explicitly chosen sampling. Extra overlapping forecasts stay out of a canonical survival curve.

Possessions shorter than one second

The way control ends decides which actions a short possession retains:

  • Pass before 1 s: only the release is a canonical checkpoint. The earlier control interval is shorter than a full carry, so it supplies no successful canonical carry. The start can be inspected as an additional snapshot.
  • Direct loss before 1 s: retain one failed carry attempt, with its checkpoint at the individual-possession start. It is a failure within the fixed one-second forecast horizon, even though the observed loss happens earlier. The loss endpoint closes the possession without starting another action.
  • Foul suffered or clearance before 1 s: no complete carry and no terminal pass/carry action are available, so there is no canonical checkpoint. Annotated snapshots remain available for inspection.

The canonical profile of a short pass or a short failed carry therefore contains one point: the release for a pass, the start of the possession for a failed carry. Any further evaluation frame is an additional snapshot.

A partial tail after full carries

For a possession lasting 2.4 s and ending in a pass, the successful canonical carries remain 0–1 s and 1–2 s. The last 2–2.4 s is a short control tail, shorter than a complete carry. Canonical checkpoints are 0, 1 and 2.4 s; 2 s is an optional snapshot.

If the same 2.4 s duration ends in a direct carry loss, retain the failed 2–2.4 s attempt. Canonical checkpoints are then 0, 1 and 2 s. The terminal action is evaluated at 2 s, before execution fails, and 2.4 s is the loss endpoint.

For a foul suffered or clearance at 2.4 s, only the carry starts at 0 and 1 s are canonical. The tail start at 2 s and terminal frame at 2.4 s are additional snapshots. The possession ends without a terminal canonical action. These timings are constructed to illustrate the segmentation rule.

Initial and final states

The initial state of an individual possession is its first canonical checkpoint. The final state is its last canonical checkpoint when control ends with a pass or a direct loss: the release in the first case and the start of the final failed carry in the second. A foul suffered or a clearance supplies no terminal action, so the possession has no final state in this sense. A possession shorter than one second has a single checkpoint, which is both its initial and its final state.

The table applies the checkpoint rules and these definitions to example durations: any duration below 1 s, and 2.0 s and 2.4 s as examples of a duration that is, or is not, a whole number of seconds. Other durations follow the same rules.

Ending Example duration Canonical checkpoints (s) Initial state Final state
Pass 2.4 s 0, 1, 2.4 0 s Release at 2.4 s
Pass 2.0 s 0, 1, 2.0 0 s Release at 2.0 s
Pass below 1 s Release only Release Release
Direct loss 2.4 s 0, 1, 2 0 s Carry start at 2 s
Direct loss 2.0 s 0, 1 0 s Carry start at 1 s
Direct loss below 1 s 0 Possession start Possession start
Foul suffered or clearance 2.4 s 0, 1 0 s None
Foul suffered or clearance below 1 s None None None

The pressure patterns of the case studies and the band cohort of the composed-risk benchmark use these definitions.

3. Start type and previous action

The pass-selection, action-selection and residual-risk models use two possession-level context variables, start_type and previous_action. The table of context variables by task lists what each task reads. This section fixes the convention for both.

Start type describes how the player obtained control. It is taken without modification from the Dynamic Events of SkillCorner, which define the categories and their annotation (SkillCorner, n.d.). The labels are listed below.

Previous action follows the convention of (Stalpaert 2022): when an action is preceded by a complete carry, the previous action is the carry, named ball_drive in the code. Otherwise the previous action is the start type. With the one-second carries of this segmentation, the rule is applied to the observed prefix of the individual possession:

  • Before a complete second of control, previous_action equals start_type.
  • From 1.0 s of control onwards, after at least one complete carry, previous_action is ball_drive; the checkpoint at 1 s already carries it.
  • The same rule applies to a pass release or an arbitrary intermediate frame.

Thus a quick pass after reception keeps the reception context, such as pass_reception, while a pass after several seconds of carrying has previous_action="ball_drive". For example, a pass released at 2.4 s follows two complete carries and has previous_action="ball_drive", whereas a pass released before 1 s keeps the start type. The field depends only on the observed prefix of the individual possession.

4. Context labels and their origin

The learned models use the granular start_type labels of the SkillCorner Dynamic Events without regrouping them. previous_action takes the same labels until a complete carry is observed, and then becomes ball_drive. In feature records these columns are named start_type_raw and previous_action_raw. SkillCorner defines the labels (SkillCorner, n.d.); the table gives a short general reading of each, and the football concepts (reception, interception, recovery and restart context) are common to providers.

Label General meaning
pass_reception Receiving an open-play pass.
pass_interception Obtaining control by intercepting an opposing open-play pass.
recovery Obtaining control of a loose or available ball.
keep_possession Retaining or re-establishing control, as distinguished from a new reception or interception by the source annotation.
throw_in_reception, corner_reception, free_kick_reception, goal_kick_reception Receiving the ball from the named restart.
throw_in_interception, corner_interception, free_kick_interception, goal_kick_interception Gaining control from the opponent’s named restart.
unknown The source explicitly leaves the start context unspecified.
ball_drive Carrying after at least one complete canonical carry; generated by PRESS for previous_action only.

A possession may begin with a restart reception and continue in active play. Keeping that start context is a separate decision from admitting a dead-ball delivery into the open-play pass-execution cohort. Pass-link and outcome filters belong to the individual task benchmarks.

The fitted encoders also contain __missing__ and __unseen__ buckets for an absent value or a category outside the fitted vocabulary. They are encoding markers. Legacy _std columns group the raw labels into open-play/set-piece reception, open-play/set-piece interception and continuation; the deployed choice and residual-risk models use the granular vocabulary instead.

For another provider, map equivalent event meanings to these labels before using the pretrained models. Preserve genuinely unavailable context as missing. Action-choice context excludes future outcomes, intended recipients and remaining possession time.

5. Context in the learned tasks

Only the tree-based tasks use context variables. The physical models, ball-drive risk and pass probability, use the tracking state alone.

Task Context variables
Pass selection Start type, previous action, match minute and score difference
Action selection Start type, previous action, match minute, score difference and completed_canonical_drives
Residual risk Start type, previous action, match minute, score difference and elapsed individual-control time

Match minute and score difference (carrier-team goals minus opponent goals) are read at the evaluated frame and do not depend on the segmentation. Start type and previous action are one-hot encoded, with buckets for missing and unseen values. The possession-level variables use only the observed prefix of the individual possession, before its eventual duration or outcome. Action selection uses the number of completed canonical carries. Carry checkpoints fall on whole seconds, whereas passes are released at arbitrary times, so the elapsed time would reveal which action follows. This follows from the segmentation choices and would be leakage. Residual risk predicts the terminal outcome of the possession, so it uses the elapsed time.

6. An observed sequence

Ivan Vujica’s possession 8_774 in Melbourne City FC–Macarthur FC lasts 2.9 s and ends with a completed pass to Luke Brattan. The table below is read from the processed match, including the noncanonical short-tail snapshot. It illustrates both the segmentation and the change in previous_action.

import os
from pathlib import Path
import pandas as pd
from PRESS import PRESS

opendata = Path(os.environ.get("SKILLCORNER_OPENDATA", Path.cwd().parent / "opendata"))
match_id = "2006229"
match_dir = opendata / "data/matches" / match_id
press = PRESS.from_skillcorner(match_dir)
individual_id = "8_774"
individual = press.get_player_possessions(individual_id)
actions = press.get_actions(
    possession_id=individual_id,
    valid_only=True,
    include_snapshots=True,
)
actions["elapsed_seconds"] = (
    actions.frame_start - individual.frame_start.item()
) / press.fps
print(actions[
    ["frame_start", "elapsed_seconds", "action", "previous_action", "is_canonical"]
].to_string(index=False))

       41454              2.0   snapshot      ball_drive         False
       41463              2.9       pass      ball_drive          True
import matplotlib.pyplot as plt
